TCP和UDP的区别

一个是可靠传输，一个是不可靠传输

TCP使用三次握手建立连接，拥有丢包重传，拥塞控制机制，保障传输安全和准度 ssh 四次挥手

UDP没有限制发包速率，容易丢包，一般用于影音 流媒体 不存在拥塞控制和分块传输

sql注入

判断有无注入点 -> 看有无回显或页面异常状况 -> 判断利用方式

判断有无注入点

1、单引号闭合 看页面是否异常 
2、永真永假判断 可以判断出字符型还是数字型

看页面有无异常状况

并不是看有没有回显，是对比原来的情况，少一张图片，文字变了也算页面异常
单引号闭合测试页面正常，有可能是waf过滤 或者url编码了

各种情况和函数

页面有回显
order by 排序函数，按表的第几列来进行排序，用来判断列数（超过了会报错） 
# 小细节：可以改用group by（分组排序） 效果一样 ； 面对过滤可以使用order by 1+1


union select 1,2,3 判断回显的位置 union会将两次select 的结果进行合并，列名使用的是前一个select的列名
# 小细节: union 前后的列数要一致不然会报错；如果原查询只返回一条数据，那么就需要让原查询结果为空如：
# ' and 1=2 union select 1,2,3 --+  # 关键！让前面的查询返回空

文件上传

文件上传功能点+文件能够解析脚本运行+知道上传的路径地址

什么是00截断
适用条件：PHP 版本 < 5.3.4，且magic_quotes_gpc=Off
原理：%00是字符串结束符，服务器会认为文件名到%00就结束了
用法：filename="test.php%00.jpg"

图片马：木马写入在图片内部，但是本身不能知执行。需要配合文件解析漏洞

# 或者指定某个文件解析为PHP
<Files "shell.jpg">
  SetHandler application/x-httpd-php
</Files>


.user.ini 绕过（PHP-FPM 专属）
auto_prepend_file=shell.jpg

XSS

未对用户输入的内容进行严格过滤和转义，导致攻击者可以注入恶意 JavaScript 代码。当其他用户访问包含恶意代码的页面时，浏览器会自动执行这段代码，从而被攻击者控制。

攻击用户

窃取cookie

配合打CSRF

钓鱼、键盘记录

反射性
存储型
DOM型
原理：恶意代码不需要经过服务器处理，而是由前端 JavaScript 直接从 URL 或其他地方获取参数，并动态插入到 DOM 中执行。
从别的地方获取恶意代码，由浏览器自动插入到页面中
1、从url后面
2、从页面跳转处获取

绕过：
各种标签绕过<script>
<img src=x onerror=alert(1)>

onerror被过滤
使用鼠标事件或者键盘事件绕过

CSRF

在没有防护的情况下，构造恶意的链接，诱导用户点击链接，执行一些用户不清楚的操作，例如发送敏感信息，执行敏感操作

例如 我拥有一套系统的源码，构造了一个添加账户的操作，但是系统是会鉴权的，如果在页面配合上xss漏洞，管理员到这个页面就会跳转，不知不觉建立了一个用户

防御方法
1、CSRF token
2、验证refer头

SSRF

利用服务器漏洞，让服务器向目标地址发送请求，由于是用服务器发起的请求，所以可以访问服务器内部的资源，内网资源，可以成为一个内网探针

利用不同的协议访问不同的资源
file://
gopher://
dict://

php反序列化

漏洞成因：反序列化函数接收的数据用户可控

反序列化时，php会调用魔术方法，自动执行函数
__wakeup()	反序列化之前自动调用	高（经常被用来做清理工作，可能有危险操作）
__construct()	对象创建时调用	低（反序列化时不会调用！很多人搞错这一点）
__destruct()	对象销毁时调用（脚本执行结束前）	极高（最常用的利用点）
__toString()	对象被当作字符串使用时调用	极高（POP 链的核心枢纽）

shiro550和721

提供用户信息存储在cookie里的功能
关键字 RememberMe
550：shiro的存储过程是序列化数据经过AES编码，base64编码后保存在cookie中
漏洞成因：AES密钥是提前写好的，有了密钥就能构造序列化数据，达到反序列化目的
721：AES密钥可以通过padding oracle进行爆破，不过需要一个已经登录的会话来爆破，这就是他们最大区别

FastJson

是ali的一款Json的解析工具，出现json的请求体就有可能有这个漏洞
漏洞关键字：@type autotype
接收@type数据，autotype 可以自动转化成这个类
流量特征：
1、正常json业务不会有@type和java类
2、jndi远程的地址
